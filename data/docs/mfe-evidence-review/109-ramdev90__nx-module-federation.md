# 109 — ramdev90/nx-module-federation

## Repository overview

Angular example in an Nx workspace, largely generated by tool scaffold. A shell and three remotes, `customer`, `orders` and `products`, each with its own entry and build (#35 through #38, #44 through #47). Architecture is supported by complete Module Federation chain:
- **Dependency:** `@nx/module-federation` supplies `withModuleFederation` used by configurations, and wrapper depends on `@module-federation/enhanced` (#2, #6).
- **Configuration:** each remote declares itself by name and exposes `./Routes` (#12, #14, #16). Shell names three remotes (#18). Each unit's webpack configurations pass these declarations to `withModuleFederation`, in normal and production builds (#13, #15, #17, #19 through #23). Shell starts development remotes through Nx federation executor (#11).
- **Code:** shell route table names three remotes (#31), and each `loadChildren` imports `<remote>/Routes` and uses exposed `remoteRoutes` (#24 through #26).
- **Relationships:** three active host → remote relationships result (#39 through #41).

No remote URL: Nx resolves names to same-workspace projects, and production URL block is merely scaffold comment (#23). No application has observed deployment; builds are separate, but only development or local servers exist (#43 through #47).

Particularity is lateral coupling outside federation: `orders` NxWelcome screen imports `ProductList` component from `products` sources and renders it (#32), producing `other` relationship orders → products (#42). Component enters `orders` bundle at build time.

Signals misleading when read alone:
- **Nx (#1, #3 through #5, #7 through #10):** monorepo tools rather than MFE tools. `@nx/js`, `@nx/webpack` and `@nx/workspace` are not even used, and `nx` has no snapshot invocation (#10). History clarifies none of these points because earlier manifest versions are unavailable (#48 through #51).
- **Asynchronous bootstrap (#27 through #30):** internal to each unit.
- **Initial application (#34, #43):** `apps/microfrontend-workspace` has its own entry and build but does not participate in composition. Fifth structural application, outside four composed units.

Repository has no architecture documentation: documentation review recorded no claim.

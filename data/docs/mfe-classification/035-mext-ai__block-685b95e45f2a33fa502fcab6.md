## Rationale for Q5

- Under a literal reading of the checklist, the case would be **MFE-unit**: the unit is explicitly prepared for an external host (`exposes`, `mount` API).
- But MF here is a **platform plugin mechanism** (MEXT): the repository is a platform template populated through its editor, and the host is the MEXT product, not the author's application. It is the same case as repository **010** (Qodly custom components), classified as Non-MFE by the researchers.
- The block is an isolated widget/mini-app embedded by the platform, not part of an application decomposed into units.

## Rationale

- Q5 is No by override, consistent with the decision for repository 010, so the repository is Non-MFE.
- If the "platform plugins" rule (suggested in 010) is not adopted, classification becomes **MFE-unit**.

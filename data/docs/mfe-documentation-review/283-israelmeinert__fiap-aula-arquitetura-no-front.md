## Leitura do repositório

Material de uma aula de arquitetura front-end, todo em português. O `README.md` da raiz apresenta 14 blocos de exemplos do mesmo domínio (EventFlow), cada um numa pasta com README próprio. Ao lado deles há o conteúdo dos slides (`conteudo/aula-arquitetura-front-end.md`, fonte da apresentação Marp `aula-arquitetura-front-end.html`) e quatro textos de apoio em `material/`: roteiro do professor, guia do aluno, exercícios e gabarito. Só o bloco 10 (`exemplos/10-micro-frontends/`) descreve unidades que se compõem, e é dele que vêm quase todas as afirmações. Os slides 67–72 (`conteudo/aula-arquitetura-front-end.md:2028-2204`) mostram a árvore e os adaptadores de montagem do bloco. O README do bloco descreve o shell, os dois remotos, o manifesto e o caminho de publicação. Os textos de `material/` repetem as frases desse README quase palavra por palavra. A documentação confere com as revisões anteriores: um shell Vite/TypeScript carrega em runtime, por `import()` de uma URL tirada de `remotes.json`, um de dois remotos (Catálogo React, Checkout Angular), cada um com build próprio e sem biblioteca de MFE (3.4.2; 3.4.5 #1, #2). ## Observações

**1. README.md:3.** O README apresenta o repositório como coleção de alternativas para o mesmo problema, uma por bloco. A revisão estrutural encontrou 29 aplicações nas pastas dos 14 blocos, e a de composição só liga as três do bloco 10. As outras 26 rodam cada uma por si. Isso confirma o desenho de exemplos paralelos, com o bloco 10 como único conjunto composto (também `frontend_units: 3` na classificação).

**2. README.md:22.** O `npm run aula -- 10` constrói os dois remotos, sobe cada um no seu servidor e só então sobe o shell (`scripts/aula.mjs:26-30`). É o único bloco que inicia mais de uma unidade frontend junta (no 13 Angular, o segundo processo é o BFF, que não é frontend, `scripts/aula.mjs:32`). As revisões anteriores registram as duas relações host → remote do bloco (3.4.5 #1, #2). A frase "O comando sobe automaticamente a API/BFF quando necessário", na mesma linha, é instrução de execução e trata de backends, por isso fica fora da tabela.

**3. README.md:28.** A tabela de endereços nomeia um "Shell dos micro-frontends". A revisão estrutural tem `exemplos/10-micro-frontends/apps/shell` como unidade (`Yes`), e a de composição o põe como origem das duas relações. A porta 4300 confere com `exemplos/10-micro-frontends/apps/shell/package.json:7`, mas é detalhe de desenvolvimento.

**4. README.md:93.** Nenhum import atravessa as pastas dos blocos. Os únicos imports que saem da pasta de uma aplicação vão para `material/estilos.css` ou, no bloco 10, para `packages/contracts` do próprio bloco (`exemplos/10-micro-frontends/apps/shell/src/main.ts:1`). O estilo de demonstração é usado por várias unidades: nas React por import (ex.: `exemplos/01-componentes/react/src/main.tsx:3`), nas Next pelo layout (`exemplos/11-renderizacao/next/src/app/layout.tsx:2`), nas Angular pelo `styles` de cada projeto do `angular.json` (ex.: `angular.json:18-20`) e no shell do bloco 10 (`main.ts:2`). Por isso é compartilhado no sentido das instruções. O "apenas" vale para código. Os exemplos também usam a mesma API didática em tempo de execução (`mocks/server.mjs`, subida por `scripts/aula.mjs:24-25`), mas ela é um backend, não regra importada.

**5. conteudo/aula-arquitetura-front-end.md:2059-2069.** A árvore do slide reproduz o bloco 10: `apps/shell`, `apps/catalogo-react` com `App.tsx` e `mount.tsx`, `apps/checkout-angular` com `app/checkout-app.ts` e `mount.ts`, e `packages/contracts/mount.ts`. Todos existem no snapshot. A árvore completa do README do bloco (`exemplos/10-micro-frontends/README.md:33-59`) repete a estrutura e confere arquivo por arquivo. O comentário "monorepo é opcional" confere com a organização observada, um workspace npm só (`package.json:9-15`; `unit_organization: monorepo` na classificação). A nota do slide ("neste recorte" não há manifesto nem fallback, `:2076`) fala do código mostrado nos slides, não do snapshot (ver Leitura).

Descoberta e fallback se confirmam: o shell busca o manifesto `/remotes.json` e resolve a URL do remoto (`exemplos/10-micro-frontends/apps/shell/src/main.ts:16-22`) e, se o carregamento falha, mostra "Aplicação indisponível" (`:30-33`).

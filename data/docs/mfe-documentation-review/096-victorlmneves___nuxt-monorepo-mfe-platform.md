# 096 — victorlmneves/_nuxt-monorepo-mfe-platform

## Repository overview

Documentation is the English root README, the only `documentation` file in `artifacts.csv`. It presents a micro-frontend platform in a monorepo: a Nuxt 3 shell orchestrating four remotes, two Vue 2 + Vuetify 2 and two Vue 3 + Vuetify 3. It includes an annotated directory tree (README.md:11-36), a "How it works" section on framework isolation, header, event authentication and `mount`/`unmount` contract (README.md:40-62), run and build instructions, steps for adding an MFE, an authentication service replacement example and port table (README.md:138-146). It also says project was built upon another repository by the author, `nuxt-mf-monorepo` (README.md:5). That origin is outside snapshot and unrelated to units, so did not become a row.

README generally matches previous reviews: five units (3.4.3), four host → remote Module Federation relationships and four event relationships (3.4.5), separate build per application (3.4.6). Differences concern what is shared. Header would be the only shared element (README.md:20, :48), but only shell uses it, while all five units use package `@mfe/shared` (3.4.2). Furthermore, Vue 3 remotes would share Vue 3 with shell through `singleton` scope (README.md:46), but shell has no `ModuleFederationPlugin` and initializes each container with empty scope (apps/shell/composables/useMfeLoader.ts:28-32). Loader comment itself says each remote manages its own scope (apps/shell/composables/useMfeLoader.ts:29-30).

Excluded from table:

- "`ShellHeader.vue` lives in the shell and is rendered by every page" (README.md:50), an internal shell detail. Login page does not use header (apps/shell/pages/login.vue:2-9); the other two do (apps/shell/pages/index.vue:3; apps/shell/pages/app/[...mfe].vue:3);

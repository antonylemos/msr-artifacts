# 174 — lorem98/mfe

## Leitura do repositório

A documentação é o README da raiz, em inglês, o único arquivo `documentation` do `artifacts.csv`. É longo e didático: apresenta o projeto como prova de conceito de micro-frontends com Module Federation do webpack 5 (README.md:1-5), explica a tecnologia, traz dois diagramas (página e grafo de federação), descreve cada pacote com uma árvore de pastas comentada, lista os "Key Concepts Demonstrated" (builds e deploys independentes, bibliotecas compartilhadas, agnosticismo de framework, execução isolada, bootstrap assíncrono) e depois trata de integração entre frameworks, roteamento, estado de autenticação, isolamento de CSS, execução, produção, CI/CD e extensão. Os `package.json` não têm `description`; quase todos os arquivos de entrada e os wrappers do container têm comentários explicativos.

No essencial, o README confere com as revisões anteriores: um container React que hospeda três remotes (marketing e auth em React, dashboard em Vue 3) por Module Federation, cada remote expondo o próprio `bootstrap` com uma função `mount`, uma rota do container por remote, e quatro pacotes com build e workflow de deploy próprios para prefixos de um mesmo S3/CloudFront. A revisão de dependências não registrou dependência das tecnologias do `dependencies.csv`; o plugin vem do próprio webpack (`webpack/lib/container/ModuleFederationPlugin`, packages/container/config/webpack.prod.js:2), o que confere com o nome "Webpack 5 Module Federation". As divergências são de generalização: o README atribui a "cada remote" o padrão de sincronização de histórico e o `mount` com browser history na execução isolada, que o dashboard não segue (afirmações 10 e 24); diz que o dashboard usa `<style scoped>` em todo SFC, mas o `App.vue` não usa (afirmação 27); e o comentário do `index.html` do auth diz que esse HTML nunca é servido, mas o build de produção o gera e o workflow o publica (afirmação 32). O compartilhamento de Vue "entre remotes Vue" é hipotético, porque só há um (afirmação 22).

## Observações

**1. README.md:3.** São quatro pacotes webpack 5 num só repositório, sem workspace, ligados por Module Federation (3.4.3; 3.4.5 #1-#3), e cada um com deploy `separado` (3.4.6 #1-#4). A tecnologia é o `ModuleFederationPlugin` do próprio webpack (packages/container/config/webpack.prod.js:2), com webpack `^5.88.0` (packages/container/package.json:26); por isso a revisão de dependências não registrou dependência específica, e o nome do README confere. O título (README.md:1) e a linha final (README.md:517) repetem o nome da tecnologia. "Production-style" é adjetivo, sem artefato a conferir.

**2. README.md:5.** Container, auth e marketing declaram `react` `^17.0.1` (packages/container/package.json:11; packages/auth/package.json:11; packages/marketing/package.json:11) e o dashboard declara `vue` `3.2.31` (packages/dashboard/package.json:13). As três relações têm a mesma forma, independentemente do framework do remote (3.4.5, Leitura). Repetição: README.md:517 ("React 17 (container, marketing, auth) + Vue 3 (dashboard) on a single page").

**3. README.md:45-52.** O container declara os três remotes com seus `remoteEntry.js` e compartilha as próprias dependências, que incluem `react` e `react-dom` (packages/container/config/webpack.dev.js:17-22). O diagrama simplifica o que cada `remoteEntry.js` entrega: os remotes expõem o `bootstrap` com `mount`, não as páginas; as páginas citadas são as rotas internas de cada remote (packages/marketing/src/App.js:19-20; packages/auth/src/App.js:18-23) e o dashboard Vue montado por `createApp` (packages/dashboard/src/bootstrap.js:12-14). A frase que introduz o diagrama (README.md:43) é definição geral e está na Leitura.

**4. README.md:54.** Cada remote tem build próprio e um workflow que só dispara com mudanças na sua pasta e publica só o seu `dist` (3.4.6 #1, #3, #4). No exemplo do marketing, o workflow publica em `marketing/latest` e invalida justamente o `remoteEntry.js` (.github/workflows/marketing.yml:7-8, 24, 30), e o container aponta para esse caminho fixo (packages/container/config/webpack.prod.js:18), de modo que não precisa ser reconstruído. Para auth e dashboard a invalidação é do `index.html`, não do `remoteEntry.js` (3.4.6 #1, #3); isso afeta o cache, não a independência do deploy. "Marketing team" é ilustração; não há artefato sobre equipes. Repetição: README.md:497 ("Because each remote is independently deployed, no other package needs to be rebuilt or redeployed").

**5. README.md:60-90.** O `Switch` do container põe o auth em `/auth`, o dashboard em `/dashboard` só com `signedIn` (redirecionando para `/auth/signin` caso contrário) e o marketing em `/` (packages/container/src/App.js:27-43; 3.4.4). A página única é o `index.html` do container, com `#root` (packages/container/public/index.html:10; packages/container/src/bootstrap.js:5). As portas do diagrama ficam fora (Leitura). Repetições: README.md:118 e 134 (o `index.html` do container como a única página), README.md:363-369 (a rota protegida), o roteiro de teste (README.md:426-431), os comentários do `Switch` (packages/container/src/App.js:26, 31, 40) e o "embedded inside the container" dos comentários dos `index.html` do auth e do dashboard (packages/auth/public/index.html:10; packages/dashboard/public/index.html:10-11).

**6. README.md:94-105.** O container é o único que declara `remotes` (packages/container/config/webpack.prod.js:17-21), e cada remote declara `exposes` (3.4.5 #1-#3); nenhum remote consome outro. O "imports at runtime" repete o mecanismo da afirmação 3. Repetições: README.md:112 e 116 ("The container is the **host application**"), README.md:121 ("Declares every other package as a Module Federation **remote**") e a árvore do container (README.md:132, `webpack.dev.js` com `ModuleFederationPlugin (remotes)`).

**7. README.md:119.** O container usa o `BrowserRouter` com o `Switch` das rotas de topo (packages/container/src/App.js:17, 25-44). Os remotes React usam `Router` com o history recebido no `mount` (packages/marketing/src/App.js:17; packages/auth/src/App.js:16), não um `BrowserRouter`. Repetição: README.md:316, primeira frase ("The container owns a single `<BrowserRouter>` with the real URL"); a árvore do container repete o mesmo (README.md:136).

**8. README.md:120.** O `signedIn` é um `useState` do container (packages/container/src/App.js:14), que o usa para o `Header` e para liberar `/dashboard` (packages/container/src/App.js:20-23, 33). O auth não guarda estado de sessão: recebe `onSignIn` e o repassa às telas (packages/auth/src/App.js:13, 19, 22). Repetição: README.md:343, primeira frase ("Auth state lives in the **container** (`useState`), not in any remote"), e o diagrama de README.md:345-352.

**9. README.md:122-123.** Os três wrappers chamam `mount(ref.current, ...)` do remote importado e renderizam uma `div` com a `ref` (packages/container/src/components/AuthApp.js:22, 26, 41; packages/container/src/components/DashboardApp.js:16, 21, 26; packages/container/src/components/MarketingApp.js:6, 10, 25), como registrou a revisão de código-fonte. Repetições: a árvore do container (README.md:141-143, "wrapper for marketing remote" etc.), o passo 3 de README.md:491 e o comentário de packages/container/src/components/AuthApp.js:13-14.

**10. README.md:122, 124.** A sincronização vale para marketing e auth: o container passa `onNavigate` e registra o `onParentNavigate` devolvido no seu history (packages/container/src/components/MarketingApp.js:10-22; packages/container/src/components/AuthApp.js:26-38), e os dois remotes usam memory history (packages/marketing/src/bootstrap.js:13; packages/auth/src/bootstrap.js:23-25). O dashboard não tem history nem roteamento: o `mount` só cria e monta a aplicação Vue e devolve um `onParentNavigate` vazio (packages/dashboard/src/bootstrap.js:12-20), e o wrapper ignora o retorno (packages/container/src/components/DashboardApp.js:18-22); a revisão de composição registrou que essa relação não troca navegação (3.4.5 #2). O comentário do próprio dashboard diz que ele "currently has no sub-routing" (packages/dashboard/src/bootstrap.js:17-18). Como a frase vale para "each remote", a parte do dashboard a desmente. Repetições, com o mesmo alcance: README.md:316 ("Each remote uses an **internal MemoryHistory** [...] The two histories are kept in sync via callbacks"), o diagrama de README.md:318-323, README.md:337 ("Each remote applies the same pattern"), os comentários de packages/auth/src/bootstrap.js:6-10, packages/container/src/components/AuthApp.js:16-19 e packages/auth/src/components/Signin.js:61-62.

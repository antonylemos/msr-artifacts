# 060 — hscale/adx-core-k

## Repository overview

Documentation is entirely in English and very extensive: 80 `documentation` files in `artifacts.csv` and 447 `doc-*` occurrences. It describes "ADX CORE" as a multi-tenant SaaS platform, "Temporal-first", with Rust backend microservices and, on frontend, a React/Vite shell composing domain micro-frontends through Module Federation (`README.md:3-35`; `adx-core/README.md:1-11`; `adx-core/docs/README.md:93-107`). The frontend documentation centers on two guides: `adx-core/docs/developer-guide/module-federation.md` (1661 lines) and `adx-core/docs/developer-guide/team-autonomy.md` (753 lines). Previous reviews confirm the basic design: shell with six remotes, one per domain, loaded through `React.lazy` under route prefixes (3.4.5 #1-#6) and configured with `@originjs/vite-plugin-federation` (3.4.2). Execution promises, however, are not confirmed. Event bus communication, shared global context, failure isolation, independent deployment and per-micro-frontend BFFs appear in text, but artifacts refute or only partially confirm them (rows 4, 9, 13, 16-20 and 22). Much documentation discusses a "completa" version (English translation: "complete") absent from the snapshot: four remotes without `index.html`, exposes pointing to missing files, workflows and scripts using root `apps/<app>` while applications are in `adx-core/apps/` (3.4.3 Notes; 3.4.6 Overview).

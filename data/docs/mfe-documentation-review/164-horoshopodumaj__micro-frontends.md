A documentação é um único README na raiz, em russo, e é o único arquivo `documentation` do `artifacts.csv` (README.md:1-138). Ele apresenta o projeto como demonstração de micro-frontends com Module Federation sobre Rspack, descreve as três aplicações e seus papéis, desenha a cadeia `host → remote → vue_remote` com os endereços `remoteEntry.js`, dá uma tabela de portas e do que cada aplicação expõe ou consome, as instruções de instalação e execução, uma árvore de pastas comentada e uma lista de "características principais". ## Observações

**1. README.md:1.** O título diz que o repositório é uma demonstração de micro-frontends com Rspack e Module Federation; a frase de abertura repete isso, "Демонстрационный проект, показывающий работу **микрофронтендов** через **Module Federation** на базе **Rspack**" (projeto de demonstração que mostra o funcionamento de micro-frontends por Module Federation sobre Rspack) (README.md:3). As três partes conferem: há três unidades frontend (3.4.3), as três declaram e usam `@module-federation/enhanced` com o plugin do Rspack (3.4.2), há duas relações federadas ativas (3.4.5 #1, #2) e as três aplicações têm build Rspack próprio (3.4.6). "Demo" confere com `repo_type: example` da classificação.

**2. README.md:5.** As três aplicações são as unidades da revisão estrutural (host, remote e vue-remote), em projetos irmãos sem workspace na raiz, cada um com `package.json`, lockfile e build próprios (3.4.3, Notas; 3.4.6 #1-#3). "Независимых" (independentes) também tem artefato: o `remote` e o `vue-remote` têm página própria e renderizam o próprio conteúdo sem o host (remote/src/App.tsx:7-14; vue-remote/src/bootloader.ts:8). A independência é de execução e de build; a do host não é completa, porque a página dele importa `remote/RemoteContent` (host/src/App.tsx:3), mas a frase não diz mais que isso.

**3. README.md:7.** O host é aplicação React (host/package.json:26) e é o contêiner: não expõe nada e consome o container `remote` (host/module-federation.config.ts:3-6), cujo componente renderiza (host/src/App.tsx:3, 19; 3.4.5 #2). "Удалённые модули" (módulos remotos) está no plural, mas o host consome um único módulo, `remote/RemoteContent`; o plural não muda o papel. A tabela repete o papel, "потребляет `remote`" (consome `remote`) (README.md:42), e a árvore o chama de "React-контейнер" (README.md:114); os dois trechos estão neste parágrafo.

**4. README.md:8.** O `remote` é aplicação React (remote/package.json:26), expõe `./RemoteContent` (remote/module-federation.config.ts:7-9) e consome o container `vue_remote` (remote/module-federation.config.ts:4-6), cujo `Counter` monta (3.4.5 #1). A tabela repete o que ele expõe e consome (README.md:43), a árvore o chama de "React-микрофронтенд" (README.md:118), e a página dele exibe "Я микрофронтенд на React" (remote/src/RemoteContent.tsx:8); os três trechos estão neste parágrafo.

**5. README.md:9.** `vue_remote` é o nome do container federado (vue-remote/module-federation.config.ts:2), e o diretório da unidade é `vue-remote` (3.4.3). A aplicação usa Vue 3 (vue-remote/package.json:26, `"vue": "^3.2.19"`) e expõe `./Counter` (vue-remote/module-federation.config.ts:5). O README não menciona a segunda entrada de `exposes`, o próprio runtime `vue` como `./vue` (vue-remote/module-federation.config.ts:6), por onde o `remote` obtém o `createApp` que monta o componente (remote/src/CounterWrapper.tsx:3, 9); é omissão, não contradição. A tabela repete o que a aplicação expõe (README.md:44), a árvore a chama de "Vue 3 микрофронтенд" (README.md:123), e o componente exibe "Я микрофронтенд на Vue" (vue-remote/src/Counter.vue:5); os três trechos estão neste parágrafo.

**6. README.md:15-31.** O diagrama liga o host ao `remote` por `remote@http://localhost:3001/remoteEntry.js` e o `remote` ao `vue_remote` por `vue_remote@http://localhost:3002/remoteEntry.js`. São exatamente as entradas de `remotes` (host/module-federation.config.ts:4; remote/module-federation.config.ts:5), e os dois fornecedores geram `remoteEntry.js` (remote/module-federation.config.ts:3; vue-remote/module-federation.config.ts:3), como registram as relações 1 e 2 da revisão de composição. A seta não liga o host ao `vue_remote`, o que também confere (3.4.5 #2). Os endereços são locais, e a revisão de build e deploy não achou outro lugar onde as unidades sejam servidas (3.4.6).

**7. README.md:34.** O host não declara o container `vue_remote` (host/module-federation.config.ts:3-5), e quem o declara é o `remote` (remote/module-federation.config.ts:4-6); o componente Vue chega à página do host só por meio do `RemoteContent` (3.4.5 #2, Observações). A lista de características repete a mesma ideia, "**Вложенная федерация** — host → remote → vue_remote" (federação aninhada) (README.md:133), e está neste parágrafo. "Federação aninhada" é o nome que o README dá ao `remote` ser ao mesmo tempo fornecedor e consumidor, como a revisão de composição descreve.

**8. README.md:46.** As três aplicações têm `rspack build`/`rspack serve` nos scripts e configuração Rspack própria (3.4.6 #1-#3; host/package.json:5, 8). A frase só diz qual é o empacotador, não fala de deploy.

**9. README.md:103-106.** O que a página do host deve mostrar é a composição encadeada das revisões anteriores: o host renderiza o `RemoteContent` do `remote` (host/src/App.tsx:19; 3.4.5 #2), e esse componente embute o `CounterWrapper` (remote/src/RemoteContent.tsx:10), que monta o `Counter` vindo de `vue_remote` (remote/src/CounterWrapper.tsx:2, 9-10; 3.4.5 #1). A descrição do `Counter` como botão de incremento confere com vue-remote/src/Counter.vue:3-4.

**10. README.md:112-127.** A árvore comentada mostra três pastas, cada uma com `src/` e `module-federation.config.ts`, com `RemoteContent.tsx` no `remote` e `Counter.vue` na aplicação Vue. Os arquivos existem (host/module-federation.config.ts:1; remote/src/RemoteContent.tsx:4; vue-remote/src/Counter.vue:1; vue-remote/module-federation.config.ts:1), mas a terceira pasta se chama `vue-remote/`, não `vue_remote/` (3.4.3). A árvore usa o nome do container federado como nome de pasta; os comandos `cd vue_remote` (README.md:62, 78) têm o mesmo erro. A parte de host e remote se confirma; a pasta `vue_remote/` não existe no snapshot, e por isso a linha é `contradita`. A divergência é só de nome: a unidade e seus arquivos estão lá. Os comentários da árvore sobre papel e porta repetem as linhas 3 a 5.

**11. README.md:134.** O componente Vue é montado dentro de uma árvore React: o `CounterWrapper`, componente React do `remote`, cria o app Vue com `createApp(Counter)` e o monta num `div` (remote/src/CounterWrapper.tsx:9-10, 16; 3.4.4, src-mount-call). "React-контейнер" é o termo que o README usa para o host (README.md:7, 18); no host, o componente Vue aparece por esse caminho, dentro do `RemoteContent` (3.4.5 #2), já que o host não importa nada do `vue_remote` (linha 7). Nas duas leituras, um componente React renderiza um componente Vue, o que confere.

**12. README.md:135.** O `vue-remote` declara `vue` como `shared` com `singleton: true` e `eager: true` (vue-remote/module-federation.config.ts:10-13). Um único runtime Vue é usado pelas duas unidades que usam Vue: o `remote` não tem `vue` no `package.json` (remote/package.json:1-29) e monta o `Counter` com o `createApp` importado de `vue_remote/vue` (remote/src/CounterWrapper.tsx:3, 9), que é o runtime exposto pelo próprio `vue-remote` (vue-remote/module-federation.config.ts:6). O runtime é compartilhado por duas unidades, e por isso a linha é `corroborada`. A ressalva é sobre o mecanismo: o `singleton` só está declarado no `vue-remote`, já que nenhuma outra unidade declara `vue` como `shared` (host/module-federation.config.ts:7; remote/module-federation.config.ts:10). Quem garante o runtime único no snapshot é a exposição de `./vue`, não a negociação do singleton.

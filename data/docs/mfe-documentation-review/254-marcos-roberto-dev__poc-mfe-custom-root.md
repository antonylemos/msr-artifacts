## Observações

**1. root-app/index.html:10.** O comentário apresenta o bloco seguinte como import map estático, de ES modules, para os microfrontends. O `<script type="importmap">` nativo está escrito no próprio HTML (root-app/index.html:11-18) e mapeia `@org/content-app` e `@org/header-app` para os dev servers dos remotos (root-app/index.html:14-15). A revisão de código-fonte o tem como `remote-resolution` `Yes` (3.4.4), e as relações 3.4.5 #1 e #4 passam por ele. Os nomes são resolvidos pelo `import()` nativo do helper (root-app/src/utils/dynamicImport.ts:15). A ressalva é a da composição: o destino de `@org/header-app` só se liga ao `topbar-app` pela URL igual à do outro host (3.4.5 #4). Ainda assim, ele é carregado e montado como parcel. Os mapas de root-app/src/importMap.json, root-app/src/importMap.dev.json e root-app/mfe-app.json repetem os nomes, mas nenhum arquivo os lê.

**2. root-app/index.html:20.** O comentário diz que o SystemJS carregado de CDN serve a microfrontends "legacy". O script está ativo (root-app/index.html:21), e o único código que usa `window.System` é o fallback do helper (root-app/src/utils/dynamicImport.ts:22-24). Nenhum microfrontend está mapeado para ele: o único `systemjs-importmap`, que apontaria `@org/header-app` para `http://127.0.0.1:4173/app.js`, está comentado (root-app/index.html:24-30). Por isso a revisão de código-fonte deixou o fallback `Undetermined` (3.4.4). O build do topbar sai em formato `system` com saída `app.js` (topbar-app/vite.config.ts:14-15), e é a esse build que o mapa comentado parece apontar. Mas nenhum host usa esse build (3.4.6 #4), e os dois carregam o topbar como ES module pelo dev server. O carregador existe e está ligado ao helper; os microfrontends que ele serviria não têm artefato ativo. Daí `parcial`.

**3. root-app/src/utils/dynamicImport.ts:2.** Diz que o helper aceita os dois formatos, ESM e SystemJS. O código confirma: `import()` nativo em root-app/src/utils/dynamicImport.ts:15 e, se ele falhar e o SystemJS estiver na página, `System.import()` em root-app/src/utils/dynamicImport.ts:22-24. O SystemJS é carregado em root-app/index.html:21. A frase final do mesmo comentário, "This allows separating modern ESM modules from legacy SystemJS modules." (root-app/src/utils/dynamicImport.ts:8), repete a mesma capacidade e não virou outra linha. A afirmação é sobre o que o helper suporta, e isso está todo no código. Que algum módulo do snapshot chegue de fato pelo caminho SystemJS é outra questão, tratada nas linhas 2 e 5.

**4. root-app/src/utils/dynamicImport.ts:5.** O `try` com `import(/* @vite-ignore */ url)` vem antes de qualquer outra tentativa (root-app/src/utils/dynamicImport.ts:13-17). Os nomes recebidos, `@org/header-app` e `@org/content-app` (root-app/src/App.vue:8-9; root-app/src/components/ParcelWrapper.vue:22), estão no import map nativo (root-app/index.html:11-18), como diz o parêntese. A revisão de código-fonte tem esse `import()` como `dynamic-loading` `Yes` (3.4.4), e é o caminho das relações 3.4.5 #1 e #4.

**5. root-app/src/utils/dynamicImport.ts:6.** O fallback está no código: no `catch` do `import()` nativo, o helper chama `System.import(url)` quando `window.System` existe (root-app/src/utils/dynamicImport.ts:18-26). O parêntese diz que esse caminho serve aos módulos do `systemjs-importmap`. Esse mapa está comentado (root-app/index.html:24-30), e nenhum outro mapa SystemJS está no snapshot. A revisão de código-fonte deixou a chamada `Undetermined` pelo mesmo motivo (3.4.4). A parte confirmada é a ordem de tentativa; os módulos do mapa SystemJS ficam sem artefato ativo. Daí `parcial`.

**6. topbar-app/src/App.vue:4.** É o título na tela do componente raiz do topbar, não um comentário: ele aparece quando um host monta a unidade. Diz que o topbar é um microfrontend. A revisão estrutural tem o `topbar-app` como unidade frontend própria (3.4.3). A entrada só exporta os lifecycles de `singleSpaVue`, com a montagem própria comentada (topbar-app/src/main.ts:6, 8-22; 3.4.4). O `root-classic` o registra como aplicação (3.4.5 #3). A cópia local em root-app/src/modules/Topbar/src/TopbarApp.vue:4 tem o mesmo título, mas o import e o uso dela estão comentados (root-app/src/App.vue:3, 7). Ela não virou outra linha.

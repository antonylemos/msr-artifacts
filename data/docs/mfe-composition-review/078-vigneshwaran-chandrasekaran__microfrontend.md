# 078 — vigneshwaran-chandrasekaran/microfrontend

## Repository overview

An educational repository with five applications: a React host (`host`) and four remotes, two React
(`react-mfe-1`, `react-mfe-2`), one Vue (`vue-mfe`) and one Angular (`angular-mfe`). All use
webpack Module Federation; Angular uses the `withModuleFederationPlugin` helper from
`@angular-architects/module-federation` (angular-mfe/webpack.config.js:23-30). Each remote
exposes a single `./mount` module, a function receiving a DOM element and mounting its entire
application there with its framework (react-mfe-1/src/mount.js:11-18, react-mfe-2/src/mount.js:7-14,
vue-mfe/src/mount.js:8-11, angular-mfe/src/mount.ts:20-32). This common `mount(element)` contract
allows the React host to mount Vue and Angular screens without knowing the frameworks.

The host declares all four remotes in two maps, a development map using local ports and a
production map using subpaths of the same domain (host/webpack.config.js:30-46), and passes them to
`ModuleFederationPlugin` (host/webpack.config.js:80-82). In the code, an `MFE_NAV` list links each
route to a `loader` with `import('<remote>/mount')` (host/src/App.jsx:31-36); a single
`MfeContainer` component calls the loader and then `mount(container)` on a host `div` (host/src/App.jsx:59-61,
87), and routes are generated from the same list (host/src/App.jsx:178-188). The Angular remote is
declared differently, through `promise import(...)`, because the `remoteEntry.js` generated by the
Angular helper is an ES module (host/webpack.config.js:26-32).

Besides the federated core, the host has a second list, `IFRAME_NAV`, with two external applications
(Route Map and Multibank) on their own domains (host/src/App.jsx:38-41), displayed through `<iframe>` on
routes in the same shell (host/src/App.jsx:95-103, 191-197). The iframes receive only the URL: there is no message
exchange or other contract with the host. These two applications are absent from the snapshot; the
classification counts seven units including them, while the structural review records five.

There is no inter-unit communication: host, react-mfe-1 and react-mfe-2 each create their own Redux store,
without sharing it, and the source code review found no events, `postMessage` or
`BroadcastChannel`. Each remote also runs independently through its `bootstrap` (for example
react-mfe-1/src/index.js:3). Joint publication builds the five projects separately and copies
each `dist` to a subdirectory of a single `dist` (package.json:9-12, vercel.json:2-3), explaining
the `/react-mfe-1/`, `/vue-mfe/` etc. paths in the production map; this is not build-time
composition.

## Observations

**1. host → react-mfe-1.** The host's `reactMfe1` remote matches the react-mfe-1 unit through
`name` and `remoteEntry.js` (react-mfe-1/webpack.config.js:45-48) and the exposed `./mount`
module (react-mfe-1/webpack.config.js:52-54), imported in host/src/App.jsx:32. The production
path `/react-mfe-1/` matches the subdirectory to which the unit's build is copied
(package.json:11); port 3001 only corroborates. Active: the host invokes the loader and calls `mount` with the
container (host/src/App.jsx:59-61) when the `/react-mfe-1` route is opened (host/src/App.jsx:178-188),
and the remote creates the React root on the received element, with its own store (react-mfe-1/src/mount.js:11-18).

**2. host → react-mfe-2.** The same pattern as relationship 1: `reactMfe2` and `./mount` in
react-mfe-2/webpack.config.js:43-47 match the host's remote (host/webpack.config.js:37, 43) and
the import in host/src/App.jsx:33; the `/react-mfe-2/` subdirectory comes from the copy in package.json:11.
The mounted function is react-mfe-2/src/mount.js:7-14.

**3. host → vue-mfe.** `vueMfe` and `./mount` in vue-mfe/webpack.config.js:59-63 match the host's
remote (host/webpack.config.js:38, 44) and the import in host/src/App.jsx:34. On the remote side,
`mount` creates an isolated Vue application and mounts it on the host element (vue-mfe/src/mount.js:8-11).
In the Code column, vue-mfe/src/mount.js:10 precedes host/src/App.jsx:178 because it follows the
source code review order (first table, then the second).

**4. host → angular-mfe.** The host does not write `angularMfe@url` as for the other remotes: it declares the
`angularMfe` key with a `promise import(...)` of `remoteEntry.js` (host/webpack.config.js:30-32,
39, 45). The match comes from the key name equaling the remote's `name: 'angularMfe'`
(angular-mfe/webpack.config.js:24) and, in production, the `/angular-mfe/` path, the remote's `publicPath`
(angular-mfe/webpack.config.js:36) and copy subdirectory (package.json:11).
`mount` creates an `<app-root>` inside the host element and bootstraps `AppModule` only on the
first call (angular-mfe/src/mount.ts:18-32); on a second route visit the element is recreated,
but bootstrap is not repeated. The analysis is static and does not check whether the screen reappears in that case;
this does not change the relationship.

**5. host → https://multibank-1.onrender.com/.** The target is the URL from `IFRAME_NAV`
(host/src/App.jsx:40), opened by the `<iframe src={url}>` in `IframeView` (host/src/App.jsx:97-98) on the
`/multibank` route (host/src/App.jsx:191-197). It is on another domain with no matching unit
in the snapshot, hence In snapshot `No`. Active `Yes` because both supporting source code review
lines are `Yes`. There is no configuration or contract beyond the URL. The target is written as
it appears in the artifact.

**6. host → https://route-map-five.vercel.app/.** The same as relationship 5, with the URL from
host/src/App.jsx:39 and the `/route-map` route. The same two code lines support relationships 5
and 6, because one component and one list serve both targets; therefore the ordering tie was
resolved by Target in alphabetical order.

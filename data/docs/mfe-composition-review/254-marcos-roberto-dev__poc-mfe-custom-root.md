# 254 — marcos-roberto-dev/poc-mfe-custom-root

## Repository overview

A single-spa proof of concept with Vue 3 in four independent projects, without a root workspace. `content-app` and `topbar-app` are Vite applications exporting only the `bootstrap`, `mount` and `unmount` lifecycles created by `singleSpaVue` (content-app/src/main.ts:8-22; topbar-app/src/main.ts:8-22). Their own mounting is commented out in both (content-app/src/main.ts:6; topbar-app/src/main.ts:6), so their UI starts only when a host calls `mount`. The other two projects are alternative hosts composing the same two remotes through the same Vite development server URLs.

`root-app` is a Vue "custom root". It does not use `registerApplication`. Its root template has two `ParcelWrapper` components, one for `@org/header-app` and another for `@org/content-app` (root-app/src/App.vue:8-9). Each wrapper loads the module by name with `dynamicImport` (root-app/src/components/ParcelWrapper.vue:21-22), attempting native `import()` (root-app/src/utils/dynamicImport.ts:15) and, if it fails, `System.import` (root-app/src/utils/dynamicImport.ts:22-24). It then mounts the module as a parcel with component `Parcel` from `single-spa-vue/parcel` and `mountRootParcel` (root-app/src/components/ParcelWrapper.vue:3-5, 10-11, 46). Names are resolved by the page's native import map (root-app/index.html:11-18). `root-classic` is the classic `create-single-spa` root config: webpack, `single-spa-layout` and an injected import map. The layout places `@org/topbar-app` and `@org/content-app` on the default route (root-classic/src/microfrontend-layout.html:20-25). Root config constructs applications from that layout, loads each through `import(name)`, registers all with `registerApplication` and calls `start()` (root-classic/src/org-root-config.ts:9-20). The import map with both units is emitted only in local mode (root-classic/src/index.ejs:29-39), enabled by `--env isLocal` in the `start` script (root-classic/package.json:4; root-classic/webpack.config.js:21-22). The production map is commented out (root-classic/src/index.ejs:27).

The name-to-unit connection is uneven. `@org/content-app` and `@org/topbar-app` repeat the `name` in the units' `package.json` files (content-app/package.json:2; topbar-app/package.json:2). However, `@org/header-app`, the name used by `root-app` for topbar, matches no snapshot name. It connects to `topbar-app` only because its URL, `http://127.0.0.1:5175/src/main.ts` (root-app/index.html:15), is the same as `@org/topbar-app` in the other host (root-classic/src/index.ejs:35). In this URL, only the port distinguishes the unit, because path `/src/main.ts` exists in both remotes. Moreover, no configuration fixes ports 5174 and 5175 (content-app/vite.config.ts:5-7; topbar-app/vite.config.ts:5-20). Hence relationship 4 retains the name as it appears in the artifact (see Observations).

What did not become a relationship. The `root-app` SystemJS map, which would point `@org/header-app` to topbar's `app.js` build, is commented out (root-app/index.html:24-30). Thus fallback `System.import` lacks a confirmed target. This path resembles the `format: "system"` build with `app.js` output (topbar-app/vite.config.ts:14-15). `root-app/src/importMap.json`, `root-app/src/importMap.dev.json` and `root-app/mfe-app.json` repeat the names with other URLs (for example, port 5173 for content in root-app/mfe-app.json:4), but no snapshot file reads them. The local topbar copy in `root-app/src/modules/Topbar/` has its import and use commented out (root-app/src/App.vue:3, 7). `import('@org/root-config')` loads the root config itself (root-classic/src/index.ejs:33, 53). `root-app` passes fixed props `{ text: 'Hello world' }` to each parcel (root-app/src/components/ParcelWrapper.vue:5, 51-53), and events `parcelMounted`/`parcelUpdated`/`parcelError` only generate host logs (root-app/src/components/ParcelWrapper.vue:3-4, 55-65). There is no inter-unit message exchange: no `CustomEvent`, `postMessage` or `BroadcastChannel` in the snapshot.

## Observations

**1. root-app → content-app.** `ParcelWrapper` with `app-name="@org/content-app"` (root-app/src/App.vue:9) loads the name through native `import()` (root-app/src/components/ParcelWrapper.vue:22; root-app/src/utils/dynamicImport.ts:15). The native import map resolves that name to `http://127.0.0.1:5174/src/main.ts` (root-app/index.html:14). The target was identified by name, repeating the unit's `name` in `package.json` (content-app/package.json:2), rather than port. The wrapper uses the module namespace itself as parcel configuration, provided it has `mount` and `unmount` (root-app/src/components/ParcelWrapper.vue:27, 33), and mounts it with `mountRootParcel` (root-app/src/components/ParcelWrapper.vue:46). These are the lifecycles exported in content-app/src/main.ts:20-22. Type is `host → remote` because the target enters as a runtime-loaded module mounted as a parcel, without orchestrator registration (`registerApplication`). Mechanism is `single-spa`, through the lifecycles and `mountRootParcel`. Active `Yes` through the `Yes` source code review lines. The `Undetermined` fallback `System.import` line (root-app/src/utils/dynamicImport.ts:24) belongs to the same loading path and does not change the value. Port 5174 depends on server startup order, being unfixed in content-app/vite.config.ts:5-7.

**2. root-classic → content-app.** The layout places `<application name="@org/content-app">` at route `default` (root-classic/src/microfrontend-layout.html:21-23). Root config transforms the layout into routes and applications and loads each through `import(name)` (root-classic/src/org-root-config.ts:9-15). It then registers applications with `registerApplication` and calls `start()` (root-classic/src/org-root-config.ts:18, 20). The name is resolved by the local import map to the same URL as relationship 1 (root-classic/src/index.ejs:34) and matches the unit's `name` (content-app/package.json:2). Type is `root-config → application` because the target enters registered in the orchestrator, although loading uses `import()`. Active `Yes` through the `Yes` lines, with the caveat that the map exists only with `isLocal` (root-classic/src/index.ejs:29-39). Content-app lifecycle lines support relationships 1 and 2 and appear in both.

**3. root-classic → topbar-app.** The same path as relationship 2, with `<application name="@org/topbar-app">` (root-classic/src/microfrontend-layout.html:22). The name is resolved to `http://127.0.0.1:5175/src/main.ts` (root-classic/src/index.ejs:35) and matches the `name` in topbar's `package.json` (topbar-app/package.json:2). Consumed lifecycles are those in topbar-app/src/main.ts:20-22. Both applications reside on the same route and are mounted together inside `<main>`. Order follows the layout: topbar first (root-classic/src/microfrontend-layout.html:20-24). Active `Yes`, with the same local-mode caveat as relationship 2.

**4. root-app → @org/header-app.** The second `ParcelWrapper` of `root-app` loads `@org/header-app` (root-app/src/App.vue:8) through the same path as relationship 1. The import map resolves that name to `http://127.0.0.1:5175/src/main.ts` (root-app/index.html:15). No snapshot unit is named `header-app`. The match with `topbar-app` appears only when comparing that URL with `@org/topbar-app` in the other host (root-classic/src/index.ejs:35). In that URL, only port 5175 distinguishes the unit, because path `/src/main.ts` is shared by both remotes and the port is unfixed in topbar-app/vite.config.ts:5-20. Because a port alone is insufficient, the target retains the name as appearing in the artifact, and In snapshot remains `Undetermined`. The commented-out topbar copy in `root-app/src/modules/Topbar/` (root-app/src/App.vue:3, 7) and `<header>` in topbar's App (topbar-app/src/App.vue:2) suggest the same target, but are not explicit matches. If the same URL in both hosts were accepted as a match, the target would be `topbar-app`, with In snapshot `Yes`, and topbar-app/src/main.ts:4, 8 and 20-22 would also enter this relationship. This does not change Summary counts because topbar-app already appears in relationship 3. Active `Yes` through the `Yes` lines in root-app/src/App.vue:8, root-app/src/components/ParcelWrapper.vue:3 and root-app/src/utils/dynamicImport.ts:15. The source code review already assigns those lines to topbar-app through the identical URL, under its criterion. This relationship only applies this stage's Target rule and does not correct it.

# 292 — jaideepsinghchauhan/Angular-MFE

## Repository overview

A tutorial example (README.md) in an Nx workspace with Angular, largely generated by the tool's scaffold (NxWelcome screens, example comments in configurations). `appshell/host` is the host, and `appshell/mfe1` and `appshell/mfe2` are Module Federation remotes. The host declares both by name (appshell/host/module-federation.config.ts:17), and each remote exposes key `./Routes`, pointing to its `entry.routes.ts` (appshell/mfe1/module-federation.config.ts:4-6; appshell/mfe2/module-federation.config.ts:4-6). All three configurations are passed to `withModuleFederation` from `@nx/module-federation/angular` (appshell/host/webpack.config.ts:1-2, 9, with an identical file in both remotes), and builds read them through `customWebpackConfig` (appshell/host/project.json:25-26). There is no remote URL: Nx resolves each name to the project in the same workspace, and the host starts remotes with executor `@nx/angular:module-federation-dev-server` (appshell/host/project.json:61-64).

Composition occurs through routes. The host loads `mfe2/Routes` and `mfe1/Routes` in `loadChildren` and uses each one's `remoteRoutes` (appshell/host/src/app/app.routes.ts:4-12); routes are registered by `provideRouter(appRoutes)` (appshell/host/src/app/app.config.ts:13) and presented through a menu with `router-outlet` (appshell/host/src/app/app.html:1-5, 17). Route `greeting` attempts to load `mfe1/GreetingRoutes` (appshell/host/src/app/app.routes.ts:13-17), which has a type declared in appshell/host/src/remotes.d.ts:8-11 but is absent from mfe1's `exposes` (appshell/mfe1/module-federation.config.ts:5-9). README.md:171-176 instructs adding that key, and the file shown immediately below (README.md:181-190) no longer includes it; the tutorial remained incomplete at this point. In the opposite direction, mfe1 exposes `./GreetingComponent` (appshell/mfe1/module-federation.config.ts:7-8), consumed by no unit: an exposure without a consumer that did not become a relationship.

The distinctive feature is shared login state. `UserService` from library `libs/shared/data` holds a signal (libs/shared/data/src/lib/user.service.ts:3-20); the host changes it through Login/Logout buttons (appshell/host/src/app/app.ts:18-23; appshell/host/src/app/app.html:6-15), and mfe1's NxWelcome reads and displays it (appshell/mfe1/src/app/remote-entry/nx-welcome.ts:9, 875-877). Mfe2 does not use the service. This became relationship 3. UI library `libs/shared/ui` (the button) is used by the host and imported by mfe1, but exchanges no messages and is not a relationship. Default application `apps/angular-monorepo` is an isolated unit, without a composition construct (source code review, Notes). The external remote in appshell/host/module-federation.config.ts:9 is a commented-out scaffold example and did not enter as a relationship.

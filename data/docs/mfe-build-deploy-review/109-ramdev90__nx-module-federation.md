# 109 — ramdev90/nx-module-federation

## Repository overview

Angular example in an Nx workspace, largely generated by tool scaffold. All builds use Nx targets: root `package.json` has no scripts (package.json:5), and each project declares in its `project.json` a `build` target with its own output in `dist/<projeto>`. Shell and all three remotes (`customer`, `orders`, `products`) use executor `@nx/angular:webpack-browser` with own webpack configuration, passing Module Federation configuration to `withModuleFederation` (shell/project.json:9-27; shell/webpack.config.ts:1-2, 9); default `production` configuration switches to `webpack.prod.config.ts` (shell/project.json:43-45, 56). Initial application `apps/microfrontend-workspace` uses standard Angular executor without federation (apps/microfrontend-workspace/project.json:9-13). The nx.json only defines cache and build dependencies (nx.json:13-38).

Everything serving applications is for development or local use. Shell starts with `@nx/angular:module-federation-dev-server` on port 4200 (shell/project.json:58-63), also starting remotes; each remote has `serve` with `@nx/angular:dev-server` on its own port, 4201 to 4203, depending on `shell:serve` (products/project.json:58-74; orders/project.json:58-74; customer/project.json:58-74). The `serve-static` targets (`@nx/web:file-server`) serve builds locally on the same ports (shell/project.json:84-91; customer/project.json:85-92). No Dockerfile, compose, CI workflow, hosting configuration or publication script is present in the snapshot, and `matches.csv` has no `ops-*`, `ci-*` or `cfg-public-path` occurrences. The `webpack.prod.config.ts` files leave the location for remote production URLs as scaffold comments only (shell/webpack.prod.config.ts:12-21), and example external remote in shell/module-federation.config.ts:9 is also a comment. Directory `dist` is in .gitignore:4.

No application has its own `package.json` or version; the only version belongs to workspace, `0.0.0` (package.json:3), unused in publication.

Thus snapshot does not show where remotes would be published in production. Shell’s only server is development server, starting remotes together (shell/project.json:58-63), and local `serve-static` (shell/project.json:84-91). No deploy or version.

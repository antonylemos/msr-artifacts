A Yarn 4 workspace with `packages/*` (package.json:5-7, :87), and Turborepo executes each package’s task `build`, with output in `dist/**` (turbo.json:4-11). Each of 18 apps has its own script `build`. In 17 React apps it is `webpack --mode production` over default configuration `openmrs/default-webpack-config`, an external package absent from snapshot (e.g.: packages/esm-patient-chart-app/package.json:13; packages/esm-patient-chart-app/webpack.config.js:1). In Angular app it is `ng build` (packages/esm-form-entry-app/package.json:13). Each package declares as output a bundle with own name in `dist/` (e.g.: packages/esm-patient-chart-app/package.json:6). Library `packages/esm-patient-common-lib` is also a workspace package, but structural review does not count it as application.

Publication follows OpenMRS 3: each app becomes an npm package `@openmrs/esm-*-app`, and an external app shell assembles these packages into an SPA. In CI (.github/workflows/ci.yml), job `build` runs `yarn verify` and builds all packages on push and pull request (.github/workflows/ci.yml:3-10, :48-52). The `pre_release`, on push, applies same version `-pre.<run>` to all packages, builds and publishes with tag `next` (`ci:prepublish`) (.github/workflows/ci.yml:86-90, :97-100; package.json:11). The `release`, on a GitHub release, builds and publishes with tag `latest` (`ci:publish`) to registry `https://registry.npmjs.org` (.github/workflows/ci.yml:126-131, :139, :158-162; package.json:10). Both scripts run `npm publish --access public` in each workspace except root (package.json:10-11). Each app is therefore released in its own package with own name and version. Script `release` increments version of all packages together (package.json:13), and snapshot has all at `10.2.0`, same as root (package.json:4; e.g.: packages/esm-patient-chart-app/package.json:3). Versioning belongs to each package and is used in publication, but advances as a group. After prerelease, job `deploy_patient_chart` only triggers an OpenMRS Bamboo plan through HTTP, rebuilding reference application outside repository (.github/workflows/ci.yml:110-124). Job also stores `dist` directories as workflow artifact (.github/workflows/ci.yml:102-108). The `bundle-size.yml` only measures build size in pull requests (.github/workflows/bundle-size.yml:28-33).

Snapshot Docker artifacts are for e2e testing, not publication. In workflow `e2e.yml`, after build (.github/workflows/e2e.yml:65-66), script `run-e2e-docker-env.sh` packages through `yarn pack` every workspace with `-app` in path, except `esm-form-entry-app` (e2e/support/github/run-e2e-docker-env.sh:8, :14-22). Then generates `spa-assemble-config.json` with these packages plus external navigation and home modules (e2e/support/github/run-e2e-docker-env.sh:29-38) and starts compose in a temporary directory (e2e/support/github/run-e2e-docker-env.sh:42-49).
